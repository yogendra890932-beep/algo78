PART 2 — CONNECT TO YOUR VPS (SSH)
═══════════════════════════════════════════════════════════════

SSH is how you type commands into your remote VPS from your laptop.

─── On Windows ───────────────────────────────────────────────

OPTION A: Use Hostinger's built-in terminal (easiest for beginners)
  1. Go to hPanel (Hostinger control panel)
  2. Click "VPS" → your server → "Terminal" (or "SSH Terminal")
  3. It opens a terminal right in your browser — no software needed!
  ← USE THIS if you're on Windows and it's your first time

OPTION B: Use MobaXterm (free, recommended for Windows)
  1. Download from: https://mobaxterm.mobatek.net/download.html
  2. Install and open it
  3. Click "Session" → "SSH"
  4. In "Remote host": paste your VPS IP address
     (find it in Hostinger hPanel → VPS → your server)
  5. Username: root
  6. Click OK → it asks for your password
     (find it in Hostinger hPanel → VPS → your server → "Root password")
  7. Type the password and press Enter
     (the password won't show as you type — that's normal)

─── On Mac / Linux ───────────────────────────────────────────

  1. Open Terminal (Mac: press Cmd+Space, type "terminal", press Enter)
  2. Type this command (replace YOUR_VPS_IP with your actual IP):

     ssh root@YOUR_VPS_IP

  3. It asks "Are you sure you want to continue connecting?" → type: yes
  4. Enter your root password when prompted

─── How to find your VPS IP and password ─────────────────────

  1. Log in to https://hpanel.hostinger.com
  2. Click "VPS" in the top menu
  3. Click on your VPS server
  4. You'll see:
     - IPv4 address: this is YOUR_VPS_IP (e.g. 203.55.12.44)
     - Root password: click the eye icon to reveal it

PART 3 — INITIAL SERVER SETUP
═══════════════════════════════════════════════════════════════

Once you're connected (you see a $ or # prompt), run these
commands one by one. Copy each line, paste it, press Enter,
wait for it to finish before doing the next one.

TIP: In MobaXterm/terminal, paste with right-click (not Ctrl+V)

─── Step 3.1: Update the server ──────────────────────────────

  apt update && apt upgrade -y

  This takes 2–5 minutes. Wait for it to finish.

─── Step 3.2: Install required software ──────────────────────

  apt install -y python3.12 python3.12-venv python3-pip \
    postgresql postgresql-contrib \
    redis-server \
    nginx \
    certbot python3-certbot-nginx \
    git curl unzip ufw

  This installs: Python, the database, Redis (for live updates),
  nginx (web server), certbot (free SSL), and tools.
  Takes 3–5 minutes.

─── Step 3.3: Verify everything installed ────────────────────

  python3 --version
  # Should show: Python 3.12.x

  psql --version
  # Should show: psql (PostgreSQL) 16.x

  redis-cli ping
  # Should show: PONG

Never run your app as "root". Create a dedicated user:

PART 5 — SET UP THE DATABASE (PostgreSQL)
═══════════════════════════════════════════════════════════════

─── Step 5.1: Start PostgreSQL ───────────────────────────────

  systemctl start postgresql
  systemctl enable postgresql
  # "enable" makes it start automatically when VPS reboots

─── Step 5.2: Create database and user ───────────────────────

  # Switch to the postgres system user temporarily
  sudo -u postgres psql

  # You're now inside the PostgreSQL console (prompt shows "postgres=#")
  # Run these commands one by one:

  CREATE USER algo_bot WITH PASSWORD 'YourStrongPassword123!';
  CREATE DATABASE algo_bot OWNER algo_bot;
  GRANT ALL PRIVILEGES ON DATABASE algo_bot TO algo_bot;
  \q

  # \q exits the PostgreSQL console
  # IMPORTANT: Replace 'YourStrongPassword123!' with your own strong password
  # Write this password down — you'll need it in the .env file

─── Step 5.3: Verify database works ─────────────────────────

  sudo -u postgres psql -c "\l"
  # Should show a list with "algo_bot" in it

PART 8 — CREATE YOUR .env CONFIGURATION FILE
═══════════════════════════════════════════════════════════════

The .env file holds your private settings. Create it:

  nano /opt/option_algo/.env

  # The "nano" editor opens. Type/paste the following,
  # replacing EVERY value marked with ← with your actual values.

─────────────────────────────────────────────────────────────
# PASTE THIS into nano (replace all ← values):

# Security Keys
SECRET_KEY=paste-a-random-64-character-string-here
FERNET_KEY=paste-your-fernet-key-here

# Database (use the password you created in Step 5.2)
DATABASE_URL=postgresql+asyncpg://algo_bot:YourStrongPassword123!@localhost:5432/algo_bot

# Redis (leave as-is — Redis runs locally)
REDIS_URL=redis://localhost:6379/0

# Your site URL (replace with your actual domain)
APP_BASE_URL=https://optiscalper.com

# Admin account (first login)
ADMIN_EMAIL=your@email.com
ADMIN_PASSWORD=ChooseAStrongAdminPassword!

# CORS (replace with your domain)
ALLOWED_ORIGINS=https://optiscalper.com

# Upstox webhook (generate a secret string)
WEBHOOK_SECRET=another-random-secret-string-here

# Email (Gmail App Password — see note below)
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your@gmail.com
SMTP_PASSWORD=your-16-char-app-password
SMTP_FROM=Optiscalper <your@gmail.com>

# Google Sign-In (optional — leave blank to disable)
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=

# Upstox redirect (replace domain)
UPSTOX_REDIRECT_URI=https://optiscalper.com/api/users/upstox/callback

# Push notifications (generate with: python scripts/generate_vapid_keys.py)
VAPID_PUBLIC_KEY=
VAPID_PRIVATE_KEY=
VAPID_CLAIM_EMAIL=your@email.com

# Server
DEBUG=false
─────────────────────────────────────────────────────────────

  # When done typing in nano:
  # Press Ctrl+X → press Y → press Enter (this saves and exits)

─── Generate SECRET_KEY ──────────────────────────────────────

  python3 -c "import secrets; print(secrets.token_hex(32))"
  # Copy the output and paste it as SECRET_KEY in .env

─── Generate FERNET_KEY ──────────────────────────────────────

  python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
  # Copy the output and paste it as FERNET_KEY in .env

─── Generate VAPID keys (for push notifications) ────────────

  cd /opt/option_algo
  source venv/bin/activate
  python scripts/generate_vapid_keys.py
  # Copy the VAPID_PUBLIC_KEY and VAPID_PRIVATE_KEY into .env

─── Gmail App Password ───────────────────────────────────────

  1. Go to myaccount.google.com → Security
  2. Enable "2-Step Verification" if not already on
  3. Go to myaccount.google.com/apppasswords
  4. Select app: Mail, device: Other → type "Optiscalper" → Generate
  5. Copy the 16-character password → paste as SMTP_PASSWORD
  NOTE: Use spaces or not — either works

─── Protect the .env file ────────────────────────────────────

  chmod 600 /opt/option_algo/.env
  chown algo_bot:algo_bot /opt/option_algo/.env

PART 11 — POINT YOUR DOMAIN TO THE VPS
═══════════════════════════════════════════════════════════════

─── If your domain is ON Hostinger ──────────────────────────

  1. hPanel → Domains → your domain → DNS / Nameservers
  2. Add a new A record:
     Type: A
     Name: optiscalper  (or @ for root domain, or whatever subdomain)
     Value: YOUR_VPS_IP
     TTL: 300
  3. Click Save
  4. Wait 5–15 minutes for DNS to propagate

─── If your domain is ELSEWHERE (GoDaddy, Namecheap etc.) ───

  1. Log in to that provider
  2. Find DNS settings for your domain
  3. Add A record:
     Host/Name: optiscalper (or @ or subdomain)
     Value/Points to: YOUR_VPS_IP
     TTL: 300 or lowest available
  4. Save and wait 15–30 minutes

─── Check if DNS is working ──────────────────────────────────

  # On your laptop terminal/command prompt:
  nslookup optiscalper.com
  # Should show YOUR_VPS_IP in the answer

  # Or visit: https://www.whatsmydns.net
  # Type your domain and check if it shows your VPS IP worldwide

PART 12 — SET UP NGINX (REVERSE PROXY)
═══════════════════════════════════════════════════════════════

Nginx sits in front of your app and handles HTTPS, compression,
and forwards requests to your Python app.

─── Step 12.1: Create nginx config ───────────────────────────

  nano /etc/nginx/sites-available/optiscalper

  # Paste this (replace optiscalper.com with YOUR domain):

─────────────────────────────────────────────────────────────
server {
    listen 80;
    server_name optiscalper.com;

    # Max upload size (for file uploads if any)
    client_max_body_size 10M;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
        proxy_connect_timeout 75s;
    }
}
─────────────────────────────────────────────────────────────

  # Save: Ctrl+X → Y → Enter

─── Step 12.2: Enable the site ───────────────────────────────

  ln -s /etc/nginx/sites-available/optiscalper /etc/nginx/sites-enabled/
  rm /etc/nginx/sites-enabled/default   # remove default nginx page
  nginx -t                              # test config (should say OK)
  systemctl restart nginx
  systemctl enable nginx

─── Step 12.3: Test without SSL first ───────────────────────

  # In your browser: http://optiscalper.com
  # Should show the Optiscalper landing page (but "Not Secure")
  # If it works → proceed to SSL

PART 14 — SET UP FIREWALL (SECURITY)
═══════════════════════════════════════════════════════════════

  ufw allow ssh        # keep SSH access

  ufw allow 443        # HTTPS

PART 15 — SET UP SYSTEMD SERVICES (AUTO-START)
═══════════════════════════════════════════════════════════════

Systemd services make your app:
  ✅ Start automatically when the VPS reboots
  ✅ Restart automatically if it crashes
  ✅ Run in the background (no open terminal needed)

─── Step 15.1: Install web service ───────────────────────────

  cp /opt/option_algo/scripts/algo_bot-web.service \
     /etc/systemd/system/algo_bot-web.service

  # Open the file and verify paths are correct:
  nano /etc/systemd/system/algo_bot-web.service

  # Make sure these lines match your setup:
  #   User=algo_bot
  #   WorkingDirectory=/opt/option_algo
  #   EnvironmentFile=/opt/option_algo/.env
  #   ExecStart=/opt/option_algo/venv/bin/uvicorn backend.main:app ...

  # Save and exit: Ctrl+X → Y → Enter

─── Step 15.2: Install worker service ────────────────────────

  cp /opt/option_algo/scripts/algo_bot-worker.service \
     /etc/systemd/system/algo_bot-worker.service

  # Verify paths (same as above):
  nano /etc/systemd/system/algo_bot-worker.service

─── Step 15.3: Enable and start both services ─────────────────

  systemctl daemon-reload

  systemctl enable algo_bot-web
  systemctl enable algo_bot-worker

  systemctl start algo_bot-web
  systemctl start algo_bot-worker

─── Step 15.4: Check they are running ────────────────────────

  systemctl status algo_bot-web
  # Should show: ● algo_bot-web.service ... Active: active (running)

  systemctl status algo_bot-worker
  # Should show: ● algo_bot-worker.service ... Active: active (running)

  # If you see "Failed" — check logs:
  journalctl -u algo_bot-web -n 50
  journalctl -u algo_bot-worker -n 50
  # Read the last few lines for the error

PART 20 — COMMON PROBLEMS AND FIXES
═══════════════════════════════════════════════════════════════

PROBLEM: Site shows "502 Bad Gateway"
FIX:
  systemctl status algo_bot-web
  # If stopped: systemctl start algo_bot-web
  # If failed: journalctl -u algo_bot-web -n 30 → read the error

PROBLEM: "Internal Server Error" on the site
FIX:
  journalctl -u algo_bot-web -n 50
  # Look for "ERROR" lines near the bottom

PROBLEM: Bot not starting / Dashboard says "Error"
FIX:
  journalctl -u algo_bot-worker -n 50
  # Look for the actual error

PROBLEM: Upstox token error / bot crashes at 3:30 AM
FIX: Refresh token every morning (see Part 18). This is expected
     — Upstox doesn't provide persistent tokens.

PROBLEM: Database connection error
FIX:
  systemctl status postgresql
  # If stopped: systemctl start postgresql
  # Check DATABASE_URL in .env matches what you set in Part 5.2

PROBLEM: Redis error
FIX:
  systemctl status redis-server
  # If stopped: systemctl start redis-server
  redis-cli ping   # should return PONG

PROBLEM: "Permission denied" errors
FIX:
  chown -R algo_bot:algo_bot /opt/option_algo

PROBLEM: SSL certificate expired (after 90 days)
FIX: Should auto-renew. To manually renew:
  certbot renew
  systemctl restart nginx

PROBLEM: Can't connect via SSH after enabling firewall
FIX: You locked yourself out!
  • Use Hostinger's browser-based terminal (hPanel → VPS → Terminal)
  • Run: ufw allow ssh
  • Then reconnect normally

PART 22 — UPDATING THE APP (WHEN YOU GET NEW CODE)
═══════════════════════════════════════════════════════════════

When you receive an updated option_algo.zip:

  1. Upload the new zip to /opt/ (same as Part 6)

  2. In SSH terminal:
     cd /opt
     systemctl stop algo_bot-web algo_bot-worker
     mv option_algo option_algo_backup    # keep old version as backup
     unzip option_algo.zip
     chown -R algo_bot:algo_bot /opt/option_algo

  3. Copy your existing .env (don't overwrite it!):
     cp /opt/option_algo_backup/.env /opt/option_algo/.env

  4. Update Python packages:
     cd /opt/option_algo
     source venv/bin/activate
     pip install -r requirements.txt

  5. Run database migration:
     python scripts/init_db.py

  6. Restart services:
     systemctl start algo_bot-web algo_bot-worker

  7. Verify:
     systemctl status algo_bot-web algo_bot-worker
     curl http://localhost:8000/health
